## 3. 神奇的随机算法 ✅ 已完成

新增随机播放模式（无限确定性随机播放列表，设计文档见桌面《随机播放.md》）：
设置页「顺序/随机」开关已接播放引擎；随机序列由无数个"块"（全部歌曲的
随机排列）首尾相连组成，只需保存一个 uint64 逻辑位置即可完整恢复现场。

实现要点（2026-09-02 完成）：
- `core/player/shuffle_player.{c,h}`：分块 + 确定性洗牌（Fisher-Yates）。
  块索引位混合 + 黄金比例常数作为 xorshift32 种子；仅缓存当前块（O(N)），
  跨块按需重洗；**缓存元素按歌曲数缩水**（N≤65535 用 uint16_t，省一半 RAM）；
  提供 `get_index_at(position)`、`find_in_block(block, global)`、
  `random_start()`（esp_random 拼 64 位真随机起点）。
- `player_controller`：随机模式下 上一曲/下一曲/自然播完 均按随机序列
  位置 ±1 推进（无限序列无边界，非顺序列表相邻曲目）；随机位置经
  config_store 持久化（uint64 拆高/低 32 位 + valid 标志）。
- **随机列表固定为当前播放目录/歌单**（与循环模式无关）：随机位置 P 映射
  到"目录内歌曲索引"（P % N），再换算全局下标 = dir_start + 索引；随机
  序列永不跨出当前目录。仅当用户从其它目录选歌时随机列表随之切换。
- 随机 + 单曲循环：自然播完保持单曲循环（原地重播），但**手动切歌始终走
  随机序列**（下一曲/上一曲 = 随机位置 ±1，与循环模式无关，仍在当前目录内）。
- **随机位置重置时机**（仅这三处重新生成，其余一律保存以便恢复）：
  1. 用户从列表指定播放歌曲（`play_song`）→ 随机取新块并在块内定位到
     该歌曲，当前位置 = 新块索引 × N + 块内偏移；
  2. 切换列表后从新列表选歌（同上，走 play_song）；
  3. 随机播放关闭后再开启 → 重新生成随机位置并定位到当前歌曲。
  上一曲/下一曲/自然播完/暂停/停止/开机恢复均保持并保存随机位置，
  断点续播回到同一首歌、同一序列（开机走 CMD_PLAY_SONG_RANDOM 不重生成）。
- 随机 + 单曲循环：自然播完原地重播；随机模式下循环模式仅单曲循环生效。

## 4. 适配 3 秒关机芯片 ✅ 已完成

成品机电源侧有长按 3 秒硬断电的关机芯片，**与 A 键（GPIO48）复用同一按键**：
长按超过 3 秒由硬件直接断电/开机，固件无法参与断电本身，只需在断电前完成保存。

实现要点（2026-09-02 完成）：
- **两种伪关机行为**（`core/utils/fake_shutdown.c` 统一流程 + 两个入口）：
  - `fake_shutdown_enter()` **普通伪关机（息屏）**：睡眠定时器/双按触发，
    关尽外设含显示屏（主动关屏省电），deepsleep，B 键（GPIO0）唤醒重启；
  - `fake_shutdown_wait_power_off()` **A 键长按 2s 伪关机（不息屏）**：
    配合电源侧 3 秒关机芯片——显示「正在保存配置」→ 保存配置、优雅停播 →
    显示「继续按上键以彻底关机\n或者按下键取消关机」→ 停外设（**不关屏**，
    画面定格在提示上）→ deepsleep；用户继续按住 A 键满 3s 即由硬件断电
    （屏幕靠**断电自然熄灭**，向用户展示"关机已完成"，主动关屏会让用户
    分不清是否真的关机）；若未断电，按 B 键（GPIO0，RTC GPIO）唤醒即
    "取消关机"（唤醒 = 重启，走正常开机流程恢复上次播放位置）。
- `button_service` 增加**长按事件**（`BUTTON_EVENT_A_LONG`/`B_LONG`，
  阈值 `BUTTON_LONG_PRESS_MS=2000` 可调）：按住满阈值即上报（无需抬起）；
  长按后抬起不再补报单击；双按交互期间不触发长按；**开机时已被按住**的键
  （如长按 3s 开机后未及时松手）首次抬起前不触发长按，避免"开机即误判
  关机"。
- 伪关机流程加 `s_shutting_down` 互斥：长按关机进行中又被双按/睡眠定时器
  触发时直接返回，避免并发停外设重复删除 I2C/SDMMC 驱动崩溃。
- ⚠ **踩坑：按键任务栈溢出**。初版在按键任务（`button_svc` 栈 3KB）里直接
  执行关机流程，创建 LVGL 提示覆盖层 + `lv_refr_now` 渲染调用链很深，
  触发 `A stack overflow in task button_svc` 自动重启（实测长按即崩）。
  已改为**独立关机任务**（`fake_shutdown_task`，8KB 栈、优先级 6）：
  两个入口只做防重入 + 创建任务后立即返回，顺带消除了睡眠定时器路径
  （`sleep_timer` 任务栈 2KB）的同款隐患。
- ⚠ **长按阈值 2000ms 实测偶发"按了没提示"**：用户按满 3s 时提示只显示约
  1 秒甚至一闪而过（伪关机流程本身还要耗时）。改为 **1200ms**
  （`CONFIG_BUTTON_LONG_PRESS_MS`，Kconfig 可调），提示显示窗口约 1.8s。
- 实测（2026-09-02）：长按 1.2s 触发 → 提示定格 → 继续按住 3s 硬件断电；
  中途按 B 键唤醒 → 重启恢复关机前播放位置（精确到秒）；流程总耗时约
  340ms，远小于 3s-1.2s=1.8s 的断电窗口。
- 断电时序：2s 触发 → 1 秒窗口内完成 NVS 保存/停播/停外设（耗时足够）；
  3s 硬件断电。屏幕定格提示（AMOLED 存储型显示，deepsleep 下保持显示；
  断电自然熄灭）。
- ⚠ 提示文字「正在保存配置/继续按上键以彻底关机/或者按下键取消关机」在
  **精简版字体**（`CONFIG_UI_SYSTEM_FONT_FULL=n`，调试用）中缺字，
  正常使用完整版字体（默认开启）可正常显示。
