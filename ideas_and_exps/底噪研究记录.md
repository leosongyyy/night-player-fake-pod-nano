# 底噪研究记录（FUTURE_PLAN 第 12 点）

> 研究目标：定位播放时 -51dB（相对音量 15 的 0 dBTP）底噪的成因，探索遮蔽/消除的可能性。
> 本文记录 2026-09 的对照实验过程与结论，供后续方向参考。

## 背景现象（原始观察）

在播放时存在 -51dB 级别的底噪，规律如下：

1. 只有灵敏度较高的耳机能听到；
2. 息屏与亮屏都有，**亮屏时音调更高**（约高一个半八度+，如前者 Do 则后者高八度 Sol），推测与核心频率相关；
3. 底噪为**断断续续的吱吱声**，按固定节律响起；切歌时先一声较长吱吱声再转短促，推测与读 SD 卡相关；
4. 亮屏与息屏的吱吱节奏几乎相同，仅音调不同；
5. **暂停时没有底噪**。

|---|---|---|---|
| 卡 A（问题卡） | 64GB | **朗科 Netac 64G** | 前几轮会话中"文件系统损坏导致播放器崩溃"的罪魁祸首卡 |

## 测量方法说明（重要，保证数据可比）

- 底噪幅度以 dB 表示，参考基准为音量 15 档时的 0 dBTP 电平；
- 人的听域 / 测量下限约为 **-74dB@1kHz**（不同频点响应不同）：低于该值即"听不到/测不到"，**不是真实读数**；
- ⚠ 跨轮次对比必须**固定同一首歌、同一音量档**，否则 3dB 量级差异会被测量条件漂移淹没（本次研究中 -62dB 与 -56dB 的"矛盾"即为测量条件不一致所致，同条件复测后两频率读数一致）。

补充记录：

- 历史（40MHz 原版固件 + 64GB 朗科卡）：-51dB；
- 首轮 20MHz + 4GB 旧卡主观初听"没有底噪"，但量化测量亮屏仍有 -56dB（主观听感易漏报，以量化数据为准；也可能与当时歌曲/音量/状态有关）；
- 实验早期 40MHz + 4GB 旧卡曾测到 -62dB，后同条件复测为 -56dB，判定为测量条件漂移；
- **新购致钛 64GB 卡（release 40MHz 固件）亮屏/息屏底噪均低于听域**
  ——同容量不同品牌一净一噪，证实底噪与**具体卡个体**相关，与容量无关。

## 结论

### 1. SD 卡频率与底噪无关（方向 1 排除）

4GB 卡在 40MHz 与 20MHz 下读数完全一致（亮屏均 ~-56dB、息屏均 < 听域）。
降频到 20MHz（`SDMMC_FREQ_DEFAULT`）对底噪**没有影响**，此方向放弃，
`core/hardware/sd_card.c` 已恢复 40MHz 高速原样。

### 2. 存在两条独立噪声路径

- **路径 A：与亮屏状态相关（CPU 240MHz / 显示活动）**
  4GB 卡亮屏 -56dB → 息屏骤降 ≥18dB 掉出听域。息屏同时改变了 CPU 频率
  （240→80MHz）、AMOLED 状态（SLEEP IN）与刷屏活动（LVGL 挂起），
  三者捆绑，尚未解耦（见"待办"）。与原始观察"亮屏音调更高、随核心频率
  变化"吻合，指向数字开关噪声（时钟谐波）经电源/地耦合进模拟域。

- **路径 B：与具体卡相关（读卡 / 卡自身特性）**
  64GB 朗科卡即使在息屏（最安静状态、CPU 80MHz 无刷屏）仍有 ~-59dB 底噪，
  不随 CPU/显示状态变化；4GB 卡同状态则掉出听域。该路径只在播放时出现
  （暂停无底噪），指向卡的读操作电流瞬态 / 总线信号质量 / 文件碎片导致
  的读取模式差异。**换一张正常的卡即可消除**（最实用结论）。

### 3. 亮屏时各卡量级接近，差异主要在息屏暴露；且与容量无关

亮屏噪声（路径 A）对朗科/旧 4GB 卡都明显（-56 vs -59dB）；真正把卡区分
开的是息屏：好卡干净、问题卡仍有 -59dB。

**致钛 64GB 新卡亮屏/息屏均 < 听域**——与朗科 64GB 同容量却一净一噪，
进一步排除"容量等级"因素：问题在**具体卡的个体特性**（读操作电流瞬态 /
总线信号质量），换一张质量可靠的卡即可彻底消除（实测验证）。

## 实用建议（已写入 README）

- 播放时若有可闻底噪，**先换一张质量可靠的 TF 卡验证**——个别质量差的卡
  会引入独立于固件的持续底噪（息屏盲听时尤其明显），固件侧无法消除；
- **朗科 Netac 64GB 已列入 README 实测黑名单**（息屏仍有 ~-59dB，实测确认）；
- **致钛 ZhiTai 64GB 实测良好**：亮屏/息屏底噪均低于听域（推荐替代）；
- 息屏本身就是对路径 A 噪声的有效"遮蔽"（多数卡息屏即不可闻）；
- 固件内调整 SD 频率无帮助（已验证）。

## 待办 / 下一步

1. **亮屏 + CPU 80MHz 解耦实验**：亮屏状态下把 CPU 固定到 80MHz（改
   `power_service` 的亮屏目标频率）测底噪——若掉出听域则路径 A 由 CPU
   时钟主导，若仍 ~-56dB 则由显示刷新（QSPI/AMOLED）主导。这决定后续
   "遮蔽"方向是调 CPU 频率策略还是刷屏策略；
2. 补测朗科 64GB × 40MHz 两状态（矩阵缺口，验证朗科卡是否也如 20MHz 一样两态均有噪）；
3. 若需进一步定位路径 B：64GB 卡格式化（排除碎片因素）后复测、换同容量
   正常卡对照、观察读卡节律与底噪节律是否同步（打点实验）；
4. 原始现象"切歌时一声较长吱吱声"——对应文件打开/首块读取的大电流脉冲，
   可在预读缓冲方向验证。

## 实验固件改动记录

- `core/hardware/sd_card.c`：`host.max_freq_khz` 在
  `SDMMC_FREQ_HIGHSPEED`（40MHz）与 `SDMMC_FREQ_DEFAULT`（20MHz）间来回
  切换做了三轮对照，**实验结束已恢复 40MHz 原样**，无遗留改动。
