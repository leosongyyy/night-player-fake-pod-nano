## 1. 设置菜单 →「电源选项」

原来是空白占位页，现在内容如下（懒加载，首次点进才构建）：

```
  典型容量      600 mAh        ← CONFIG_PMU_BAT_CAPACITY_MAH（默认 600，纯展示）
  当前电量      85% / 未知
  充电中        是 / 否 / 未知
  电池电压      4190 mV / 未知
  电池健康保护  开 / 关         ← 点击切换，立即生效（写 NVS + 下发给 PMU）
  （下方只有一条说明，用户指定文案；页面不再有居中的「电池信息/电池保护」标题）
```

- **刷新**：页面自建 1s `lv_timer`，只在页面可见时读一次 PMU（约 1~2ms），不读就不打扰总线。
- **"未知"的规则**：PMU 不可用或读数越界时统一显示「未知」，**不显示 0 mV / 0%** 这类假数据。
- **充电中**：严格按"是否仍在充电"判定——`0x01[2:0] == DONE`（已充满）显示「否」，
  避免"插着充电器显示充电中"的误导（状态栏的闪电图标仍沿用原 `charging` 语义）。
- 典型容量来自 Kconfig，改 `idfc build` 会自动重新配置；不参与任何计算，只用于展示。

## 2. 不显示电池温度（TS 是固定电阻，不是 NTC）

真机观察：温度始终显示 39℃ → 本板 **TS 脚接的是固定电阻（没有 NTC）**，
AXP2101 读到的是恒定电压，换算出的"温度"没有任何物理意义。因此：

- 设置页**移除「电池温度」一项**（用户要求）；`battery_info_t` 也不再带温度字段；
- `axp2101_read_status()` 不再读 TS（每次状态读取少 2 次 I²C 事务）；
- **保留** `axp2101_read_ts_mv()` / `axp2101_ts_mv_to_celsius()`：以后换用带 NTC 的电池可直接接上（📅 其 `pmu_ts_temp` 纯函数测试随 2026-11-14 移除硬件自检时一并去掉）。
- 历史修正（保留）：TS 通道 ADC 是 **0.5 mV/LSB**（`Table 6-5`），原驱动把原始码
  当 mV 返回（300mV 读成 600），已修正为 `raw/2`。

## 3. 电池健康保护：软件限充（**不是**把 CV 降到限充电压）

> **当前阈值（2026-11-16 用户要求上调）**：充到 **4.08V（4080mV）** 停充、放电到
> **3.98V（3980mV）** 恢复（100mV 回差）。数值定义在 `battery.h` 的
> `BATTERY_CARE_STOP_MV` / `BATTERY_CARE_RESUME_MV`，充电专用界面
> （`boot_flow` 的"已到上限"判定）也用同一组宏，不要在别处写死数字。
> 早期版本是 4.0V / 3.9V，本文下面"4.0V"字样属于当时的记录，机制不变。

AXP2101 **没有**"充到 X% 停止"的寄存器（充电全程由 PMU 自主完成，电量计只上报）。

**第一版尝试（已废弃）**：直接把 `0x64[2:0]` 的恒压目标从 4.2V 改成 4.0V。
真机复现出严重副作用：

- 电池此时是 4.17V（高于 CV 4.0V）→ PMU 判为"充电完成/电池高于目标"并**断开 BATFET**；
- 正常使用中拔掉充电器 → VSYS 没有电池来源 → PMU 以 **DCDC 欠压保护**硬断电
  （实测 `0x21=0x20`，即 bit5 DCDC_UV，不是软件关机）。

因此改为 **CV 保持 4.2V + 软件限充**：

- 开关写入 NVS 键 `battcare`；`battery_set_health_protection(on)`：
  - 始终把 CV 设回 **4.2V**（避免"电池高于 CV"导致 BATFET 断开）；
  - 立即读 VBAT：`on && VBAT >= BATTERY_CARE_STOP_MV` → 写 `0x18[1]=0` 停充；
    否则保持充电。
- `battery_health_protection_tick()`（正常使用由 `power_service` 1s 守护任务调用，
  充电界面由 `chg_mon` 调用）：
  - 保护开启：VBAT ≥ `BATTERY_CARE_STOP_MV` 停充；
    VBAT ≤ `BATTERY_CARE_RESUME_MV` 恢复充电（迟滞，防抖）；
  - 保护关闭：兜底确保充电已恢复。
- 这样 PMU 不会进入"完成/高于目标"状态，**BATFET 保持导通**，正常使用拔电继续用电池；
  充电界面拔电也能先显示"正在关机"再由固件写 `0x10[0]=1`。
- 代价：保护依赖固件常驻（PMU 任务挂了就停在"充电中/停充"的当前状态，不会过充）；
  阈值按电压判定，受负载/内阻影响；PMU 上电默认 CV 已是 4.2V，开机时按 NVS 重新下发。
- 设置页说明（用户指定，**只保留这一条**）：
  「开启电池健康保护后，充电会限制在约80%-90%左右，以延长电池寿命，
  建议定期充满一次来校准电量显示。」
- 仍保留 `axp2101_set_charge_voltage()`（CV 档位）给以后"更保守的 4.1V 满电"用，
  但**电池健康保护不再调用它改 CV**。

## 4. 开机原因（`core/hardware/boot_reason.*`）

`boot_reason_init()` 在 `battery_init()` 之后调用一次，只读采样并打印：

| 来源 | 读什么 | 说明 |
| --- | --- | --- |
| 主控复位原因 | `esp_reset_reason()` | POWERON / EXT_PIN / SW / DEEPSLEEP / PANIC / WDT… |
| 主控唤醒原因 | `esp_sleep_get_wakeup_causes()` | IDF 6.1 起旧 `..._cause()` 已 deprecated；返回位图，未睡眠时只有 `BIT(UNDEFINED)` |
| PMU 本次开机来源 | AXP2101 `0x20` | bit0=PWRON 按键、bit2=VBUS、bit4=电池插入、bit1=IRQ、bit5=EN |
| PMU 上次关机原因 | AXP2101 `0x21` | bit1=软关机、bit0=PWRON 长按、bit3=VSYS 欠压… |

`boot_reason_is_charger_boot()`（进充电界面的判据，全部满足）：

1. PMU 可读，`0x20` bit2（VBUS 插入）置位；
2. `0x20` bit0（PWRON 按键）**未**置位——同时按了键就按正常开机处理，避免被锁在充电界面；
3. 主控复位是"上电类"：`ESP_RST_POWERON` **或** `ESP_RST_EXT`。
   本板 PMU 的 PWROK 接在主控复位/EN 上，实测可能报 EXT，故两者都接受；
   **不是** `ESP_RST_SW`（含充电界面里按住上键 0.6s 后的 `esp_restart`）、`DEEPSLEEP`、panic/WDT；
4. 唤醒位图只有 `BIT(ESP_SLEEP_WAKEUP_UNDEFINED)`（不是 deep/light sleep 唤醒）。

> 真机观察（2026-11-14，COM3）：esptool 烧录后复位原因 = `USB (11)`、`0x20=0x01`（按键）；
> 说明 `0x20` 是**PMU 自己上电时锁存**的（主控复位不会清），也验证了"SW/复位 ≠ 充电开机"。

## 5. 充电专用界面（插电自动开机）

`main.c` 判定为 charger boot 后：

- **只初始化到 `battery_init()`**：显示/LVGL/字体/触摸/AXP2101 已有；随后构建充电界面、
  `app_main` 直接返回。**不初始化** RTC / 音频 / pldata / SD / 播放列表 / 按键服务 /
  `power_service`（省电，也不会在充电时放歌）。
- 界面：**大环**（`lv_arc`，330px，从 12 点开始顺时针填满一圈，22px 圆头描边）+
  环中心大号百分比（montserrat_48）+ 状态（正在充电 / 已充满 / 充电已停止 /
  未在充电 / 电池信息不可用）。**没有提示文字**（三行提示已按用户要求移除）。
  环颜色：充电中黄、已充满/已停止绿、不可用灰。亮度 = 用户配置，但**下限 128**。
  最下方小字**只在电池健康保护开启时**显示「电池健康保护：开启」；关闭时整条隐藏
  （用户要求：未开启保护时不显示提示文字）。
- **保护性停充时的环**：电池健康保护开启、且已到限充上限（`BATTERY_CARE_STOP_MV`）
  被软件停充时，大环画成
  **完整一圈**（绿色）表示"充电已停止"，**不再按实际电量画弧**；环中心仍显示实际
  百分比（例如 82%），状态显示「充电已停止」。保护关闭或未停充时按实际电量画弧。
- **10 秒无按键自动息屏**：AMOLED `display_sleep_enter()`（DISPOFF + SLEEP IN）+ 挂起 LVGL；
  由 `chg_mon` 任务每 50ms 轮询计时。
  ⚠ 与 `power_service` 不同：这里**在持 LVGL 锁时** `lvgl_port_suspend`，避免"解锁后 LVGL
  刚好拿到锁并卡在 handler 里被挂起 → 锁永不释放"的竞态。
- **按任意键亮屏**：上键按下沿（PMU 按住状态）或下键 GPIO61 按下沿（去抖）→ 亮屏。
- **按住上键满 0.6s → 进入正常系统**：`esp_restart()`。PMU 的 IRQLEVEL 最短 1s、做不到
  0.6s，所以由固件按"按住时长"计时（50ms 轮询），与"按住电源键开机"的语义一致；
  按住期间屏幕会先亮起，到 0.6s 直接重启。重启后复位原因是 `ESP_RST_SW`，
  `boot_reason_is_charger_boot()` 自然为 false，不会再回到充电界面（即用户建议的方案）。
- **拔掉充电器 → PMU 关机**：宽限 1.5s 后（防上电抖动）调用
  `fake_shutdown_charger_unplugged()` → 统一关机链（deep_worker 12KB 内部栈）：
  息屏时先亮屏 → 显示「充电器已断开，正在关机...」→ 挂起 LVGL → 写 `0x10[0]=1` 断电。
  充电模式下没有播放/SD/NVS 写入，关机链里的保存现场/停播/卸 SD 都是无操作。
- 监控任务 `chg_mon`：PSRAM 栈 4KB、prio 4、Core1；每 200ms 读一次 PMU（电量/电压/VBUS），
  亮屏时 1s 刷新界面；不做 LVGL 渲染（深链交给 deep_worker）。

### 已知行为/限制

- **满电/保护停充时拔电**：软件限充下 BATFET 保持导通，正常使用拔电会继续用电池；
  只有 PMU 自身判定"充电完成"（例如电池被充到 4.2V 后）才可能断开 BATFET，
  此时拔电是硬断电（无提示，但充电/正常使用中都没有进行中的 flash 写，无数据风险）。
- 充电界面是**静态画面**（只有电量数字变化）。插着充电器长时间停留在此界面时，
  建议后续考虑更低亮度/定时熄灭（当前不做，按需求保持"显示当前电量"）。
- 若 PMU 不可用（I2C 异常），无法判断插电开机，走正常开机流程（不会进充电界面）。

### 5.1 「插着充电器关机」→ 重启进充电界面（2026-11-16 新增）

**问题**：以前上键长按 / 睡眠定时到点都是直接写 `0x10[0]=1` 让 PMU 断电。PMU 一断，
固件就没了，于是：

- **4.08V 软件限充失效**——插着电过夜会一路充到 4.2V，健康保护形同虚设；
- **电量计重新起算**——E-Gauge 每次上电重算，读数漂移；
- 低电保护、电池电压监控也都停了。

**做法**：把这两个"用户意图关机"的入口改成**分流**（`fake_shutdown_user_off()`，
见 `core/utils/fake_shutdown.c`）：

| 当时状态 | 行为 |
|---|---|
| 插着充电器（`vbus_present` 或 `charging`） | 保存现场 → 停解码 + CS43131 pop-free 掉电 → 置 RTC `0x03` 的 **bit2** → `esp_restart()` → 开机流程看到标志进充电界面。**PMU 不断电**，限充/电量检测继续每秒运行。 |
| 没插充电器 / PMU 读数不可用 | 保持原来的 PMU 真断电（不插电还赖在充电界面只会耗电，而且充电界面唯一的真关机入口就是拔电） |

细节：

- 标志是**一次性**的：表世界开机在 `rtc_init()` 之后立刻消费并清 bit2
  （`fw_switch_*`，见 `RTC_BOOT_PARTITION.md` §1）；bootloader 只清分区位、不碰 bit2。
- 重启前必须 `player_controller_shutdown_audio_for_switch()`：复位瞬间 I2S 时钟直接停，
  DAC/耳放若仍上电会留下爆音/余音（充电界面不初始化音频，余音会一直挂着）。
- 提示文案是「正在进入充电界面...」（最少可见 0.5s，与关机提示同一套逻辑）。
- 进充电界面后：拔掉充电器 → 1.5s 后真断电；按住上键 0.6s → 回正常系统。
- 低电关机（<5% 60s）与"息屏未播放超时关机"**不走这条分流**，仍是真断电：
  前者必须断电防过放，后者本来就带"充电中不关机"的条件。
- **注意**：进充电界面这条路径在开机判定里与"插电自动开机"同级
  （`boot_reason_is_charger_boot() || bit2`），日志会打 `reason: shutdown reboot flag`。

## 7. 真机验证

**已在真机（debug，COM3）确认**：

- 正常开机不受影响（boot_reason 打印复位/唤醒/PMU 开机来源后照常进主界面）。
- 硬件自检新增 `pmu_ts_temp` 通过；TS 诊断打印
  `TS pin = 300 mV (fixed resistor, no NTC; battery temperature not available)`
  （本板无 NTC，不再显示温度）。
- 驱动/自检/构建 debug + release 均通过（无 warning）。
- **用户实测通过**：关机后只插 USB → 出现「正在充电」大环界面；10 秒自动息屏；
  按上/下键只亮屏；按住上键满 0.6s 重启进入正常系统（大环/无提示文字为 2026-11-14 后续调整）；
  充电界面拔掉 USB → 显示「充电器已断开，正在关机...」后断电。
- **用户实测通过**：设置 →「电源选项」四项数值（典型容量/当前电量/充电中/电池电压）
  与电池健康保护开关正常。
- **用户实测发现并已修复的问题**：第一版把 CV 降到 4.0V，电池 4.17V 时 PMU 进入"高于目标/
  完成"状态（0x18 的充电使能位被 PMU 自己清成 0、BATFET 断开），**正常使用拔充电器会
  DCDC 欠压硬断电**（0x21=0x20）。改为软件限充（CV 4.2V + 到上限写 `0x18[1]=0`）后复测：
  ① 正常使用拔电继续用电池；② 充电界面拔电显示关机提示后由固件断电——两项均正常。
- 修复后开机实测：`charge CV -> 4.2 V`、`0x18=0x08`（停充）、`status1=0x28`（BATFET 导通）。
- 修复后再测：充电界面拔电后的下一次开机日志里 `0x21=0x02`（bit1 软件关机）而不是
  `0x20`（DCDC 欠压），说明拔电时 VSYS 撑住了，固件成功写了 `0x10[0]=1`。

**后续可观察项**：

- 保护开启时，放到约 3.98V 应能看到 `battery care: ... resume charging`，再充到 4.08V
  出现 `stop charging`（1s 轮询 + 100mV 迟滞，正常）。日志里的 mV 值直接来自宏，
  覆盖 4.0V/4.08V 两种历史阈值。⚠ 实机读数与宏可能差几 mV（PMU 电压 ADC 精度），
  停充点判定用 `>=`，不受影响。
- 电池满到 4.2V（关闭保护充满）后拔电仍可能是 PMU 完成态硬断电，属 PMU 行为；
  充电界面拔电的"先提示再关机"只保证在 BATFET 导通时生效。
