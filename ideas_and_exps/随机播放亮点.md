# 随机播放亮点 — NightPlayer 无限确定性随机播放

> 本文档总结 FakePodNanoNightPlayer 随机播放功能的设计亮点与实现要点。
> 算法原型来自设计文档《无限确定性随机播放列表》（桌面《随机播放.md》），
> 结合嵌入式（ESP32-S3）与音乐播放器实际场景做了落地增强。
>
> 相关代码：`core/player/shuffle_player.{c,h}`（算法模块）、
> `core/player/player_controller.c`（接入播放引擎）、
> `core/storage/config_store.c`（随机位置持久化）、`ui/settings_page.c`（开关入口）。

---

## 1. 一句话亮点

> **只保存一个 uint64 数字，就能完整恢复"无限长、不重复、可回退"的随机播放现场；**
> **随机列表固定锁定当前目录，上一曲/下一曲永不跳出当前歌单。**

---

## 2. 算法核心：把"无限"变成"有限块的循环"

传统随机的两个极端——真随机（生日悖论，频繁重复）与有限打乱（列表有边界、重打乱后可能紧接刚听过的歌）——在本设计中都被解决：

- **无限序列** = 无数个"块"首尾相连，每个块是**当前随机列表**全部歌曲的一个**随机排列**：
  `Block_0, Block_1, Block_2, …`
- **位置映射**：逻辑位置 `P` → `块 = P / N`、`块内偏移 = P % N`（N = 列表歌曲数）。
- **确定性随机**：块只依赖块索引——用「块索引哈希」作伪随机种子，对 `[0..N-1]` 做
  Fisher-Yates 洗牌即得该块的排列。**同一个位置，永远得到同一首歌**。

由此获得三个体验红利：

| 特性 | 表现 |
|---|---|
| **无限性** | 序列理论上无穷长，永远不会"播完"，适合长期后台播放 |
| **无重复** | 任意连续 N 首歌内绝不重复（每块是完整排列） |
| **断点续播** | 保存一个 `uint64 position` 即可完整恢复现场，还能无限"回到上一曲" |

## 3. 嵌入式优化亮点（针对 ESP32-S3）

| 优化点 | 做法 | 收益 |
|---|---|---|
| **缓存缩水** | 列表歌曲数 ≤ 65535 时缓存用 `uint16_t`（2B/元素），超出才用 `uint32_t` | 几百首的目录只需 KB 级内存，省一半 RAM |
| **确定性 PRNG** | 自研 xorshift32（3 条移位异或），块间种子用位混合 + 黄金比例常数 `0x9e3779b9` | 极快、无外部依赖、种子 0 已规避（否则洗牌退化为固定反序） |
| **只缓存当前块** | 块缓存 O(N) 空间；顺序播放平均 O(1)，仅跨块时 O(N) 重洗一次 | 无论播放到多远，内存占用恒定 |
| **真随机起点** | 开启随机/重新随机时用硬件 RNG `esp_random()` 拼 64 位起点 | 每次开启序列都不同，且无需熵池 |
| **边界防御** | 位置 `P` 直接取模进块，`块×N ≤ P` 天然无溢出；上一曲到 0 钳位 | 64 位位置可播 10^14 年以上，无感 |

> 缓存只是 `[0..N-1]` 的一个排列，**与具体目录无关**——目录切换后排列可安全复用，
> 无需额外重洗。

## 4. 关键设计决策（经用户确认）

### 4.1 随机列表 = 当前播放目录（固定，与循环模式无关）

- 随机位置 `P` 映射到**目录内歌曲索引**（`P % N`），再换算全局下标 `dir_start + 索引`；
- **上一曲/下一曲/自然播完永不跨出当前目录**（`P % N` 恒在目录内，序列天然封闭）；
- 仅当用户**从其它目录的列表选歌**时，随机列表随之切换到新目录（同时重新随机）。

### 4.2 随机位置重置时机（严格三处，其余一律保存）

| 时机 | 行为 |
|---|---|
| ① 用户从列表**指定播放歌曲** | 重新随机：随机取新块，在块内定位到该歌曲，当前位置 = 块×N + 偏移（"随机取新子列表 + 在该子列表里找到播放歌曲的位置"） |
| ② 用户**切换列表**后选歌 | 同上（走 `play_song`，随机列表随目录切换） |
| ③ **随机播放关闭后再开启** | 重新生成随机位置并定位到当前歌曲，之后切歌从新序列继续 |

其余情况（上一曲/下一曲/自然播完/暂停/停止/关机/**开机恢复**）**均保持并保存随机位置**，
保证断点续播回到同一首歌、同一序列、同一目录。

### 4.3 随机 × 单曲循环

- **自然播完**：保持单曲循环（原地重播，随机位置不变）；
- **手动切歌**：始终走随机序列（位置 ±1），不被单曲循环困住，仍在当前目录内。

### 4.4 降级策略

空目录 / 缓存分配失败（内存不足）时，随机开关**自动回退顺序播放**并同步持久化，
设置页图标与实际行为保持一致，绝不"开着随机却按顺序播"或卡死。

## 5. 工程集成

```
settings_page（开关）
      │ player_controller_set_shuffle(on)
      ▼
player_controller（Core0 任务，命令队列串行）
      │ CMD_SET_SHUFFLE / CMD_PLAY_SONG / CMD_PLAY_SONG_RANDOM
      ▼
shuffle_player（算法：块生成 / 位置映射 / 定位）
      ▼
playlist（目录数据）→ mp3_player（播放引擎）
```

- **命令隔离**：新增 `CMD_SET_SHUFFLE`（开关切换）与 `CMD_PLAY_SONG_RANDOM`
  （开机恢复专用，**不重新生成**）；用户选歌仍走 `CMD_PLAY_SONG`（随机模式下自动触发重新随机）。
- **持久化**：config_store 新增随机位置三键（`shuf_pos_hi/lo` + `shuf_pos_val`），
  随 last_song 在切歌/暂停/停止/关机时同步写入，开机自动恢复。
- **UI 同步**：开关状态经 config_store 变更回调实时同步设置页图标（顺序/随机）。
- **开机恢复流程**：读 last_song → 确定随机列表目录 → 恢复位置或生成随机起点 →
  `CMD_PLAY_SONG_RANDOM` + `CMD_SEEK` 回到上次进度。

## 6. 验证情况

- ✅ `idfc build` 编译链接通过；固件 ~3.75MB（分区余量 40%）。
- ✅ 已烧录真机（COM12）并完成哈希校验，设备重启正常。
- 建议真机验证路径：
  1. 设置页开启「随机播放」→ 切歌只在当前目录内随机；
  2. 从别的目录选歌 → 随机列表切换到该目录；
  3. 单曲循环下等一首自然播完 → 原地重播；手动切歌 → 随机切歌；
  4. 关机/重启 → 回到上次随机播放的目录/歌曲/进度；
  5. 关闭随机再开启 → 序列重新生成。
